Scripts and Code Provenance

Recovered and reconstructed computational materials

🎯 Purpose

This page documents the provenance of the computational materials associated with the Mathematics 2025 article.

It intentionally contains no result figures. Experimental results are presented on the project home and in the analytical notebook.

🧭 Provenance categories

The repository uses three explicit provenance labels:

  • Recovered / adapted — based directly on code preserved in the original Google Colab notebook.
  • Reconstructed — recreated from methodological details published in the article.
  • Published values — transcribed from the paper and not presented as newly recomputed outputs.

This distinction prevents reconstructed material from being misrepresented as original source code.

📓 Original notebook

The recovered Google Colab notebook should be preserved unchanged in:

notebooks/
└── 2025_Mathematics_Computers_recovered.ipynb

It contains original material for:

  • PM2.5 data preparation;
  • exploratory analysis;
  • QSVM/Qiskit experimentation;
  • classification metrics;
  • and supporting figures.

No complete original LSTM implementation was recovered from the notebook.

🧠 Reconstructed LSTM

The LSTM reconstruction follows the model-specific configuration reported in the article:

  • Plaza Castilla PM2.5 time series;
  • training period 2017–2023;
  • external test period 2024;
  • one LSTM layer with 64 units;
  • dense output layer;
  • 50 epochs;
  • Adam optimizer;
  • MSE loss;
  • MinMax normalization.

Published metrics used as reference:

RMSE = 15.98 µg/m³
MAE  = 4.42 µg/m³
R²   = 0.05

The reconstructed script is not claimed to reproduce those values exactly because the full original execution environment and preprocessing implementation were not preserved.

⚛️ Recovered QSVM

The recovered notebook preserves a Qiskit-based quantum classification workflow.

The article describes:

  • ZFeatureMap;
  • three qubits;
  • depth 2;
  • angle encoding;
  • fidelity-based quantum kernel;
  • statevector simulation;
  • 25 µg/m³ binary threshold.

The recovered code relies on a legacy Qiskit API and may require an environment compatible with the versions used during the original experiment.

⚠️ Published-method discrepancies

Two internal discrepancies in the article are relevant for reproduction:

  1. Data split: the general methodology section describes an 80/20 split, while the dedicated LSTM section describes 2017–2023 training and 2024 external testing.
  2. R²: the dedicated LSTM results table gives R² = 0.05, whereas a later comparative table contains a different value.

The repository preserves these discrepancies explicitly and does not silently harmonise them.
